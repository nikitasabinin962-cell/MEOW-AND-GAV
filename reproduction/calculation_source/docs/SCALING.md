# Типовая модель: запуск для другого региона

Башкортостан — пример применения. Программа `econtypes` построена как типовая модель для любого субъекта РФ:
региональные особенности вынесены в один раздел конфигурации, а основные данные федеральные и одинаковы
для всей страны.

## Что от региона не зависит

Признаки МО, пять слоёв сети, семь методов кластеризации, ICVI с нормировкой на случайные перестановки,
автоматический выбор числа типов, бутстреп, проверка на новых годах, 13 индексов, корреляции, случайный лес,
правила рекомендаций, отчёт и дашборд. Всё региональное задаётся в `config.yaml` (раздел `region`) и
читается модулем `econtypes/region.py`; остальной код не привязан к конкретным МО.

## Данные

| Источник | Покрытие | Для модели | Обязателен |
|---|---|---|---|
| СберИндекс: траты по МО, расстояния, доступность рынков | вся Россия: ≈2 100 МО с тратами, ≈2 570 территорий с расстояниями | 3 слоя сети, структура трат | да (файлы общие, менять не нужно) |
| Реестр контрактов ЕИС, 44-ФЗ | все регионы | госзаказ, потоки между МО (слой сети) | да (выгрузка по заказчикам региона) |
| БД ПМО Росстата | все МО РФ | зарплаты, занятость по отраслям | желательно |
| Численность населения по ОКТМО (Росстат) | все МО РФ | расчёт на жителя, доля горожан | да |
| Границы МО (geoBoundaries / OpenStreetMap) | вся Россия | карта дашборда | да (скачиваются командой `econtypes geo`) |
| Демография территориального органа Росстата | у каждого региона своя публикация | рождаемость, смертность, миграция | нет |
| Закон о бюджете субъекта (дотации на выравнивание) | у каждого региона свой | бюджетная зависимость | нет |
| Данные минфина субъекта (трансферты, рейтинг открытости) | у каждого региона свои | только внешняя проверка | нет |

Если необязательного источника нет, соответствующий признак пропускается, модель строится на остальных.

## Что делается автоматически

* **Привязка поставщиков и заказчиков к МО по ИНН.** Таблица «код инспекции ФНС → МО» строится по самим
  данным: для каждого кода берётся МО, чьё название чаще всего встречается в наименованиях заказчиков.
  Отбор «своих» поставщиков — по коду субъекта в ИНН (`region.inn_code`).
* **Сопоставление идентификаторов СберИндекса с названиями МО** — по совпадению рядов.
* **Число типов** — по нормированным ICVI.
* **Названия типов.** На первом запуске тип получает имя по двум признакам, сильнее всего отличающим его от
  остальных МО (например, «Тип 3: выше доля горожан, ниже рождаемость»). Содержательные названия можно задать
  позже через «якорные» МО (`viz.cluster_anchors`).

## Запуск за пять шагов

1. Скопировать `config/config.yaml` в `config/<регион>.yaml` и заменить разделы по образцу
   `config/region_template.yaml`: `region` (название, код в ИНН, центр), пути к данным, `geo.adm1_name`, `viz.title`.
2. Выгрузить реестр контрактов ЕИС по заказчикам региона и склеить: `econtypes add-eis папка 2023`.
3. Положить численность населения по ОКТМО и (по возможности) выгрузку БД ПМО в `data/raw/<регион>/`.
4. `econtypes --config config/<регион>.yaml geo` — границы МО.
5. `econtypes --config config/<регион>.yaml all` — база, модель, проверки, индексы, выводы, дашборд.

Перенос проверяется автотестом `tests/test_region.py`: конфиг другого субъекта (Татарстан, код ИНН 16)
меняет код региона, центр и ориентиры карты, привязка ИНН отсеивает заказчиков чужого субъекта,
а типы без якорей получают автоматические имена.

## Что потребует внимания

* **Муниципальные округа.** В части регионов районы преобразованы в муниципальные округа; программа
  обрабатывает их так же, как районы.
* **Мало МО.** В регионах, где МО меньше 25–30, типов будет меньше, а порог минимального размера кластера
  (`clustering.min_cluster_size`) стоит уменьшить.
* **Особые МО** (ЗАТО, анклавы без дорожных расстояний) задаются в `region.manual_inn_prefixes` и `region.enclaves`.
* **Межрегиональная типология.** Сеть и метрики устроены одинаково для всех регионов, поэтому данные
  нескольких субъектов можно объединить и получить общую типологию МО. Для этого `region.inn_code` нужно
  будет расширить до списка кодов — небольшая доработка.
